1. 회원 가입 및 주소 등록
사용자가 쇼핑몰에서 회원 가입을 진행하면 **회원 테이블(회원)**에 데이터가 저장됨.
아이디, 비밀번호, 이름, 이메일 등 정보 저장
회원이 배송지 주소를 등록하면 배송지 주소 테이블에 데이터가 저장됨.
아이디(FK)로 회원과 연결됨
우편번호, 주소, 상세주소 저장
한 회원이 여러 배송지를 가질 수 있음 (1:N 관계).

2. 상품 관리
관리자는 상품 카테고리 테이블에 카테고리 데이터 등록
각 상품은 상품 테이블에 등록되고, 카테고리와 연결됨
상품번호, 카테고리 코드, 상품명, 가격, 재고수량, 설명, 등록날짜
상품의 이미지는 상품 이미지 파일 테이블에 저장됨
상품번호(FK)로 상품과 연결

3. 상품 조회 및 댓글
사용자가 상품 페이지를 열면 상품 테이블에서 상품 정보와 상품 이미지 파일 테이블에서 이미지 정보 불러옴
상품 댓글(리뷰)은 상품 댓글 테이블에서 불러옴
대댓글 구조(부모댓글번호, 답글순서, 답글깊이)로 구현

4. 장바구니 흐름
사용자가 특정 상품을 장바구니에 담으면 장바구니 테이블에 데이터가 저장됨
아이디(FK) + 상품번호(FK) + 수량
회원은 장바구니에서 담은 상품을 수정하거나 삭제할 수 있음

5. 주문 및 결제 흐름
사용자가 결제를 진행하면 주문 테이블에 주문 데이터가 생성됨
주문번호(PK), 아이디(FK), 주문날짜, 처리상태(주문 접수/배송 중/완료 등)
주문한 상품별로 주문 상세 테이블에 데이터가 저장됨
주문번호(FK), 상품번호(FK), 수량, 가격
결제 테이블은 ERD에 미완성으로 보이지만, 일반적으로는 다음 데이터가 필요함
결제금액, 결제수단(카드/계좌이체/포인트 등), 결제일시, 결제상태
결제가 완료되면 재고 차감 로직이 실행되어 상품 테이블의 수량(재고) 업데이트

6. 배송 흐름
주문 시 선택한 배송지 주소를 배송지 주소 테이블에서 불러와 주문과 연결
배송 상태는 주문 테이블의 처리상태로 관리 (예: 배송 준비 중 → 배송 중 → 배송 완료)

7. 주문 완료 후
주문 완료 시 회원은 상품 댓글 테이블에 리뷰 작성 가능
관리자는 상품 조회수(상품 테이블)와 판매 현황 분석 가능

데이터 흐름 요약 (간단 다이어그램)
회원가입
→ 회원/배송지 등록
→ 상품 조회
→ 장바구니 담기
→ 주문 생성
→ 주문 상세 기록
→ 결제 처리
→ 재고 차감
→ 배송 진행
→ 상품 댓글 작성

개선해야 할 설계
주문 테이블에 **배송지 주소 ID(FK)**를 추가하는 게 일반적

## 수정 예시 ##
[ 배송지 주소 ]
배송지주소ID (FK)  ← 추가
우편번호
주소
상세주소

[ 주문 테이블 ]
주문번호 (PK)
아이디 (FK)
배송지주소ID (FK)  ← 추가
주문날짜
처리상태

- 이렇게 하면 -
주문 시 어떤 주소로 보냈는지 정확히 기록 가능
회원이 나중에 주소를 수정해도, 과거 주문 기록은 그대로 유지됨 (데이터 무결성)
